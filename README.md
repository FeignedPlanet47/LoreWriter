# NovelForge

Android-приложение для создания интерактивных новелл на Kotlin + Jetpack Compose с аккаунтами и серверной синхронизацией.

## Что входит

### Android

- регистрация, вход и выход из аккаунта;
- защищенное хранение access/refresh token через Android Keystore + AES/GCM;
- локальный Room-кэш, разделенный по пользователям;
- офлайн-работа после ранее успешного входа;
- синхронизация новелл с сервером;
- визуальная схема истории и переходы;
- рукопись новеллы;
- редактируемый Word-документ и экспорт DOCX;
- персонажи;
- rich text в узлах;
- preview, валидация, TXT/JSON экспорт;
- системная проверка орфографии Android (текущая экспериментальная интеграция сохранена).

### Server

Папка `server/` содержит:

- FastAPI;
- PostgreSQL;
- SQLAlchemy;
- Alembic migrations;
- Docker Compose;
- Argon2id password hashing;
- JWT access token;
- rotating refresh token;
- привязку каждой истории к владельцу;
- optimistic revision check, чтобы более старая копия не перезаписала новую молча.

## Архитектура

```text
Android / Jetpack Compose
        |
        | HTTPS + Bearer access token
        v
FastAPI / Python
        |
        v
PostgreSQL
```

Room остается локальным кэшем. Изменение сначала сохраняется локально, затем приложение пытается отправить полный снимок истории на сервер. При временном отсутствии сети история остается `dirty` и синхронизируется позже.

## Первый запуск сервера

```bash
cd server
cp .env.example .env
```

Обязательно замените `POSTGRES_PASSWORD` и `JWT_SECRET`.

Секрет JWT:

```bash
openssl rand -hex 64
```

Запуск:

```bash
docker compose up --build
```

После старта:

- health: `http://localhost:8000/health`
- Swagger в development: `http://localhost:8000/docs`

Подробности: `server/README.md`.

## Подключение Android к API

В `data/build.gradle.kts`:

```kotlin
debug -> http://10.0.2.2:8000/api/v1/
release -> https://api.example.com/api/v1/
```

`10.0.2.2` работает для Android Emulator. Для реального телефона в debug замените адрес на IP компьютера в локальной сети.

Перед release обязательно замените `https://api.example.com/api/v1/` на настоящий HTTPS-домен.

В основной release-сборке cleartext HTTP запрещен. HTTP включается только debug-манифестом для локальной разработки.

## Безопасность входа

Пароли намеренно не шифруются обратимо и не сохраняются на телефоне. На сервере хранится только Argon2id-хеш пароля.

- пароль передается серверу только по HTTPS в production;
- access token короткоживущий;
- refresh token случайный и ротируется;
- в PostgreSQL хранится только SHA-256-хеш refresh token;
- токены на Android шифруются AES/GCM ключом из Android Keystore;
- JWT проверяет срок, issuer, audience и подпись;
- сервер фильтрует каждую историю по `owner_id` текущего пользователя;
- release Android запрещает HTTP;
- `server/.env` исключен из Git.

## Room migrations

Текущая версия Room: **5**.

- `1 -> 2`: форматирование текста;
- `2 -> 3`: рукопись и персонажи;
- `3 -> 4`: Word-документ;
- `4 -> 5`: пользователь-владелец, cloud ID/revision и состояние синхронизации.

Старые локальные новеллы без владельца при первом входе после обновления привязываются к первому вошедшему аккаунту, чтобы не потерять существующие данные.

## Поведение при выходе

Выход разрешен даже без сети. Если перед выходом сервер недоступен, несинхронизированные истории остаются в локальном кэше этого пользователя и не показываются другому аккаунту. После повторного входа тем же аккаунтом синхронизация продолжится.

## Проверка сборки в подготовленном комплекте

- Python-файлы сервера проверены через `python -m compileall`;
- модуль `domain` проверен локальным `kotlinc`;
- полную Android Gradle-сборку в среде подготовки завершить не удалось, потому что Gradle 8.13 отсутствовал в локальном кэше, а доступ к `services.gradle.org` был недоступен. В Android Studio с интернетом выполните Gradle Sync и `./gradlew assembleDebug`.

## Подтверждение email при регистрации

Новая регистрация требует подтверждения адреса электронной почты. После нажатия «Создать аккаунт» NovelForge отправляет 6-значный код и открывает отдельный экран подтверждения. Только после успешного ввода кода пользователь получает access/refresh tokens и доступ к синхронизации историй.

В локальном Docker-окружении используется Mailpit: `http://localhost:8025`. Для production необходимо настроить реальный SMTP в `server/.env`.
